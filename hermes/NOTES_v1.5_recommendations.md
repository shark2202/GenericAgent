[agentskills.io](https://agentskills.io) format:

**Naming collision to remember:** two different `cangjie-skill` repos exist —
Yeadon8888's (person cognitive-implant, upgrade of nuwa, "think like not talk
like") and kangarooking's (book/content, RIA-TV++ pipeline). Specify which
when citing "仓颉.skill".

## Where hermes v1 sits

hermes v1's `distill()` (`plugins/skill_evolution.py:111`) is a **one-shot
create/patch** — the nuwa/cangjie *distill* stage, not darwin's *evolve*.
The dormant `fitness` frontmatter field + `_auto_patch_counts` + `.prev`
snapshots are the **seed of darwin's evolve loop**. v1.5 is the bridge from
one-shot distill to light evolution.

## Ecosystem patterns hermes should adopt

### R1 — Wire the v1.5 negative-signal hooks (planned v1.5 work)
- **Gap:** `_on_tool_after` (`plugins/skill_evolution.py:184-190`) and
  `_on_turn_after` (`:193-198`) are literal `return` no-ops.
- **Do:** `_on_tool_after` — track consecutive `code_run`/`file_patch`
  failures from `ctx['ret']` (StepOutcome error status); ≥3 →
  `handler._evolution_signal={'type':'consecutive_failures',...}`.
  `_on_turn_after` — detect `ask_user` correction (user reply ≠ agent
  candidate) → `handler._evolution_signal={'type':'correction'}`.
  Signal already flows into `distill()` via the `[trigger_signal]` prompt
  block (`:123`).
- **Double duty:** the same accumulator feeds R5's post-patch ratchet eval.
  Document one source of truth for both consumers.

### R2 — Independent scorer/gatekeeper between generate and apply
- **Gap:** `distill()` (`:111-152`) is a single LLM call that both generates
  the op and trusts it; the only gate is structural `validate_skill`. darwin
  blacklists anti-pattern #1 "same AI both modifies and evaluates"; cites 46.4%
  self-eval accuracy. nuwa/cangjie use dual-agent blind testing.
- **Do:** insert a second independent LLM call between
  `op = _parse_op(content)` (`:146`) and `_apply_op(handler, op)` (`:150`).
  Scorer rates reusability / verifiedness / non-redundancy (trimmed nuwa
  5-dim). Only `_apply_op` if score ≥ threshold; else queue a Brief marked
  "candidate failed review". Separate messages list + distinct prompt role —
  independence by construction (scorer sees output, not generator reasoning).
- **Insert:** new `_score_op(client, op, history, catalog)` in `distill()`.

### R3 — Per-skill `test-prompts.json` + empirical scoring
- **Gap:** hermes skills are single `SKILL.md`; no test-prompts. darwin scores
  by running test prompts (Phase 2.5); cangjie/X-growth ship `test-prompts.json`
  + `test-results.md` per skill. darwin principle #2: dual evaluation =
  structural + empirical; hermes has only the structural half.
- **Do:** when `distill()` creates a skill, also generate `test-prompts.json`
  (2-3 trigger scenarios). Scorer (R2) consumes them — v1.5: scorer rates how
  the current SKILL.md answers them; v2: actually execute. Write alongside
  SKILL.md in `do_skill_manage` create path (`ga.py:523`).

### R4 — Require honesty/boundary declaration (signature pattern, lowest effort)
- **Gap:** hermes frontmatter has no boundary field; `validate_skill`
  (`skill_loader.py:403-430`) requires only name+desc+heading. Every ecosystem
  skill must declare what it *cannot* do (specific out-of-competency domains,
  cutoff dates): "一个不告诉你局限在哪的 Skill，不值得信任." darwin's
  Failure-Mechanism-Encoding + Actionable-Specificity dims; cangjie's `B`
  (Boundary) dim.
- **Do:**
  - (a) add `boundaries:` (or `does_not_apply:`) frontmatter field — extend
    `parse_provenance` (`skill_loader.py:378`);
  - (b) require a boundary section (`## 适用边界` / `## 不适用` / `## 失败模式`)
    in the body — enforce in `validate_skill` (`:428`, alongside the `## ` check);
  - (c) extend the distiller `create` prompt (`plugins/skill_evolution.py:133`)
    to require the field + section.
- **Highest value-to-effort.** Most aligned adoption.

### R5 — Ratchet: revert patches that regress on the next same-class task
- **Gap:** `_apply_op` (`plugins/skill_evolution.py:76-108`) keeps a patch
  whenever `do_skill_manage` returns `status=='ok'` — but `ok` means "wrote +
  structurally valid", not "improved". darwin: baseline only rises; regressions
  auto-revert.
- **Do:** after a patch, on the *next* task in the same `task_class`, compare
  R1's negative-signal accumulator before/after. If worse, auto
  `revert_skill_prev(path)` (`skill_loader.py:469`) + reset that skill's
  `_auto_patch_counts`. Needs R1 signals + R8 fitness-log + task-class
  clustering (already defined in spec §L2 (A)).

## Code-level findings while reading hermes (fix these)

### R6 — Fix the breaker-reset bug (v1.5 correctness)
- `_auto_patch_counts` (`plugins/skill_evolution.py:37`) increments on success
  (`:104`), trips breaker at ≥5 (`:88`), but is **never reset** — the comment
  at `:36` claims "前台修正时重置" but no reset code exists. After 5 auto-patches
  a skill is permanently breaker-locked until process restart.
- **Fix:** expose `reset_auto_patch_count(name)` in the plugin; call from
  `do_skill_manage` (`ga.py:471`) when `skill_write_origin != 'background_review'`
  (foreground = human-in-loop touch) and on any `revert`.

### R7 — Wire-or-remove the dead `_consecutive_auto_distills` counter
- `_consecutive_auto_distills` (`:38`) is incremented (`:105`) and reset (`:108`)
  but **never checked** — no gate reads it. `MAX_CHANGES_PER_DISTILL=3` (`:31`) is
  also dormant (v1 emits ≤1 op). Either wire a global consecutive-distill breaker
  per spec's "无人工修正" intent, or delete the dead counter + dormant constant.

### R8 — Confirm the §7 fitness-log write is implemented
- Spec §机制 7 requires appending `(ts, action, source_turns, signal)` to
  `memory/skill_exp_<name>.md`. I see **no** such write in `distill`/`_apply_op`
  (`plugins/skill_evolution.py`) or `do_skill_manage` (`ga.py:471-617`).
  §v1不做 defers "fitness 评分(score_state)" to v2 — but the *append-log* (§7)
  seems distinct from *scoring*. The log is the **data substrate R5 needs**;
  without it, no before/after comparison. Confirm scope + implement if missing.

### R9 — Add loadability check to `validate_skill` (minor spec drift)
- Spec §实现接口 says `validate_skill` must confirm
  `get_skill_detail(name)` doesn't return `status=='error'`. Actual
  `validate_skill` (`skill_loader.py:403-430`) only checks frontmatter + heading.
  A patch that keeps frontmatter+heading but breaks the loader parser is kept.
- **Fix:** add the `get_skill_detail(name)` check on the patch path (after write,
  before declaring ok; `skill_loader.py:605` region in ga.py).

## What hermes already does right (confirmed against ecosystem)

- Avoids darwin's `git reset --hard` anti-pattern — uses `.prev`/`.bak` file
  snapshots (`shutil.copy2`) + `revert_skill_prev`, no git involved.
- Follows darwin principle #1 (single editable asset per cycle) — `distill()`
  emits ≤1 op; dormant `MAX_CHANGES_PER_DISTILL=3` is a backstop.
- Brief flush is correctly batched — `turn_end_callback` flushes at `turn%10`
  or task end (`ga.py:818-820`).
- `distill()` swallows all LLM-call exceptions silently (`:139-144`) — fine for
  v1; v1.5's fitness-log (R8) should record distill attempts/failures, not just
  successes.

- Full 9-dimension rubric (darwin's 100-pt) — v2+.
